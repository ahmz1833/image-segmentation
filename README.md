# Malware Classification Based on Image Segmentation

Reproducible PyTorch implementation of Wanhu Nie's 2024 paper, **[Malware Classification Based on Image Segmentation](paper.pdf)** ([arXiv:2406.03831](https://arxiv.org/abs/2406.03831)). The project converts the Microsoft Malware Classification Challenge (BIG 2015) byte streams into grayscale images, separates PE sections into image channels, fine-tunes VGG16 and ResNet50, and produces Kaggle-compatible probability submissions.

> **Scope.** This is a static-analysis pipeline: it reads the `.bytes` and `.asm` files supplied by BIG 2015 and does not execute malware. The dataset is nevertheless untrusted research material; keep it outside the repository and handle it in an isolated environment.

## Method at a glance

Malware bytes are interpreted as grayscale intensities. The paper argues that malware from the same family often retains recognizable texture and section-level patterns, even when its layout changes. Four PE sections are used here: `.text`, `.rdata`, `.data`, and `.rsrc`.

| Scheme | Representation | Intended information |
|---|---|---|
| **S1** | Original bytes; width selected from Nataraj et al.'s file-size table | Conventional adaptive-width baseline |
| **S2** | Original bytes; width is approximately the square root of file size | Variable-width baseline |
| **S3** | Original bytes at a fixed width of 1,024 | Fixed-width texture and layout |
| **S4 (Split)** | Each selected PE section is compacted into a separate 1,024-wide channel | Section texture without whole-file spatial layout |
| **S5 (Mask)** | One full-size channel per section; non-section pixels are zeroed | Partial spatial layout, at the cost of sparse channels |

S1-S3 are repeated into three channels. S4/S5 section combinations become multi-channel inputs. VGG16 is restricted to the six three-channel configurations listed by the CLI; ResNet50 supports all 14 committed combinations and replaces its first convolution when more than three channels are needed. Every channel is resized to 224 x 224 before ImageNet-style normalization.

![S1-S5 representations for one Ramnit sample](docs/assets/segmentation-schemes.png)

The figure above is generated by the committed `malware-seg visualize` implementation. S4 compacts section bytes; S5 preserves their positions and masks everything else.

## Dataset

[Microsoft Malware Classification Challenge (BIG 2015)](https://www.kaggle.com/c/malware-classification) contains 10,868 labeled training samples and 10,873 unlabeled test samples from nine families. The class imbalance is substantial: Simda has only 42 training samples, whereas Kelihos_ver3 has 2,942.

| Class | Family | Training samples | Class | Family | Training samples |
|---:|---|---:|---:|---|---:|
| 1 | Ramnit | 1,541 | 6 | Tracur | 751 |
| 2 | Lollipop | 2,478 | 7 | Kelihos_ver1 | 398 |
| 3 | Kelihos_ver3 | 2,942 | 8 | Obfuscator.ACY | 1,228 |
| 4 | Vundo | 475 | 9 | Gatak | 1,013 |
| 5 | Simda | 42 |  | **Total** | **10,868** |

![One S3 sample from each BIG 2015 family](docs/assets/malware-family-gallery.png)

These are visualizations, not rendered executable screenshots: each pixel is one byte value and black regions can include zero padding or masked content.

## Installation on a new machine

Requirements:

- Linux or another system with Python 3.10
- 7-Zip (`7z` or `7zz`); on Ubuntu: `sudo apt install p7zip-full`
- A Kaggle account that has joined the competition and accepted its rules
- An NVIDIA GPU is strongly recommended for the complete experiment; install a CUDA-compatible PyTorch build for the local driver if the default pip build is unsuitable
- Generous storage: the two source archives are about 37 GB together, and preprocessing, temporary batches, checkpoints, and predictions require substantially more. Reserving roughly 80-100 GB is prudent.

```bash
git clone https://github.com/ta-tahmasebi/image-segmentation.git
cd image-segmentation

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -e .

malware-seg --version
malware-seg --help
```

The package installs the `malware-seg` command. `requirements.txt` is also provided for non-editable environments; `requirements-dev.txt` adds Ruff.
```bash
DATA_DIR=~/.cache/kaggle/BIG2015/main
malware-seg download --data-dir "$DATA_DIR"
```

The downloader requests `train.7z`, `test.7z`, `trainLabels.csv`, `sampleSubmission.csv`, and `dataSample.7z`. A manual Kaggle download also works, provided `train.7z`, `test.7z`, and `trainLabels.csv` are placed directly in `DATA_DIR` with exactly those names.

### Preprocess once

Preprocessing extracts the large archives in bounded batches, pairs each sample's `.asm` and `.bytes` files, converts unknown bytes (`??`) to zero, and writes compressed S1-S5 arrays. It is restart-friendly: existing `.npz` files are skipped unless `--overwrite` is used.

```bash
malware-seg preprocess train --data-dir "$DATA_DIR"
malware-seg preprocess test  --data-dir "$DATA_DIR"

# Optional: render 10 deterministic examples per class.
malware-seg visualize --data-dir "$DATA_DIR" --samples-per-class 10
```

Check `processed/train/manifest.json` and `processed/test/manifest.json` under `DATA_DIR`. A complete run should report 10,868 training and 10,873 test samples, with failures investigated rather than silently ignored.

## Reproduce the experiments

List the exact configurations encoded by the committed source:

```bash
malware-seg configs vgg16
malware-seg configs resnet50
```

The command used for the reported paper-epoch reproduction was:

```bash
malware-seg run-all \
  --data-dir /home/amirmahdi/.cache/kaggle/BIG2015/main \
  --device cuda
```

`run-all` does **not** download or preprocess the dataset. It trains VGG16 for 20 epochs and ResNet50 for 15 epochs, then predicts the test set for every supported configuration. Defaults mirror Table 4 of the paper:

| Model | Epochs | Effective batch | Initial LR | Scheduler | Weight decay | Momentum |
|---|---:|---:|---:|---|---:|---:|
| VGG16 | 20 | 8 | 0.001 | None | 0.0005 | 0.9 |
| ResNet50 | 15 | 64 | 0.01 | Exponential decay, gamma 0.9 | 0.006 | 0.9 |

### Main observations

- The paper's best result is ResNet50/S3 at 0.0265. In the paper-epoch reproduction, the best **Public** result is ResNet50/S5 (imgs-1024 + `.text` + `.data`) at 0.02341, while the best **Private** result is ResNet50/S5 (imgs-1024 + `.text` + `.rdata`) at 0.03185.
- The best 10-epoch Public result is ResNet50/S3 at 0.02722; its best Private result is ResNet50/S1 at 0.03735. More epochs are therefore not uniformly better, but the paper-epoch run produces the strongest overall Private score.
- Among the paper-epoch reproduction's Private scores, only VGG16/S2 improves on its corresponding paper result (0.05046 versus 0.0547). Close Public scores can coexist with a weaker Private score, so architecture selection should use the Private column and repeated seeds rather than Public-only tuning.
- S4 and section-only S5 configurations reproduce poorly relative to S1-S3 and the mixed S5 variants. This is consistent with the paper's warning that compacting discards layout, masking creates sparse inputs, and changing the number/meaning of pretrained channels complicates transfer learning.
- These are single-run Kaggle scores. No confidence intervals can be inferred without multiple seeds, and Public/Private values are evaluations on different hidden subsets, not two measurements on identical samples.

### Training-set diagnostics

The committed training code reports last-epoch training accuracy/loss, then evaluates the final model on the **same full training set** to calculate macro F1, per-class metrics, and confusion matrices. These are useful implementation checks but are optimistically biased and must not be presented as validation/test accuracy.

| Model/configuration | Epochs | Last-epoch train accuracy | Train loss | Full-train macro F1 | Time |
|---|---:|---:|---:|---:|---:|
| VGG16/S3 | 20 | 99.9448% | 0.001642 | 0.9981 | 63.0 min |
| ResNet50/S3 | 15 | 99.9540% | 0.004349 | 1.0000 | 16.3 min |
| ResNet50/S5 (imgs-1024 + .text + .data), best Public | 15 | 99.9632% | 0.004347 | 1.0000 | 15.6 min |
| ResNet50/S5 (imgs-1024 + .text + .rdata), best Private | 15 | 99.9816% | 0.004494 | 1.0000 | 15.4 min |

![ResNet50 S3 training curves](docs/assets/resnet50-s3-training-curves.png)

![ResNet50 S3 training-set confusion matrices](docs/assets/resnet50-s3-confusion-matrices.png)

The perfect post-training S3 confusion matrix is not contradictory to the 99.954% last-epoch accuracy: the latter is accumulated online while model weights change throughout the epoch, whereas the former evaluates the final frozen weights. It is still a training-set result, not evidence of perfect generalization. Detailed precision, recall, and F1 are available in the generated `classification_report.csv`; the compact visualization is stored at [`docs/assets/resnet50-s3-per-class-metrics.png`](docs/assets/resnet50-s3-per-class-metrics.png).

## Output layout

All runtime outputs are rooted at the selected `--data-dir`:

```text
DATA_DIR/
├── train.7z, test.7z, trainLabels.csv
├── processed/
│   ├── train/<class>/<sample>.npz
│   ├── train/manifest.json
│   ├── test/<sample>.npz
│   └── test/manifest.json
└── artifacts/
    ├── visualizations/class_<n>/<sample>.png
    ├── models/<model>/
    │   ├── model_comparison.{csv,png}
    │   └── <configuration>/
    │       ├── model.pt, metrics.json, history.csv
    │       ├── classification_report.csv, training_predictions.csv
    │       └── training_curves.png, confusion_matrices.png, ...
    └── submissions/<model>/
        ├── prediction_comparison.{csv,png}
        └── <configuration>/
            ├── submission.csv, predictions.csv, summary.json
            └── class_distribution.png, prediction_uncertainty.png, ...
```

`submission.csv` is the file to upload to Kaggle. Test confidence and entropy plots are label-free diagnostics; they are **not** accuracy estimates.
